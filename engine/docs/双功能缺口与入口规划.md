# 爽点厂 HookForge · 双功能缺口分析与入口规划

> 基于 0.5.10-workflow-explorer 代码审查，2026-10-25
> 双功能 = ① 学习闭环（comfyui_feedback）② 主动探索 + 工作流产出（workflow_explorer）

---

## 一、双功能缺口分析

### ① 学习闭环（comfyui_feedback）— 现状 vs 缺口

| 能力 | 现状 | 缺口 |
|------|------|------|
| 实跑→历史采集 | `record_step` 采 peak_vram / elapsed / OOM / redo | ✅ 已有 |
| 历史→矩阵校准 | `adaptive.run_feedback` 写 matrix.adaptive.yaml | ✅ 已有 |
| 校准→下轮生成 | `generate_workflow` 可指向 adaptive_out_path | ✅ 已有（但 CLI 默认没传 adaptive 路径，需手动 `--matrix`） |
| 多轮累积学习 | 历史文件追加，`run_feedback` 每次全量重算 | ⚠️ 缺增量学习：重算代价随历史行数线性增长，无 TTL/衰减 |
| 学习报告可读性 | 返回 dict，无人类可读摘要 | ⚠️ 缺"本批学了什么"的中文摘要（i18n 已覆盖 UI，但学习报告本身没接） |
| 学习回流触发时机 | 只在 `auto_repair=True` 时触发 | ⚠️ 缺 `--learn-only` 独立触发（不出片，只采数据回流矩阵） |

### ② 主动探索 + 工作流产出（workflow_explorer）— 现状 vs 缺口

| 能力 | 现状 | 缺口 |
|------|------|------|
| 识别未验证组合 | `next_exploration_plan` 扫描 matrix × history | ✅ 已有 |
| 智能打分排序 | OOM / 本地 / 显存 三维打分 | ✅ 已有 |
| 渲染可执行工作流 | `emit_comfyui_workflow` 7 节点真实 JSON | ✅ 已有 |
| 工作流→ComfyUI 回灌 | `run_exploration_batch` POST /prompt | ✅ 已有（本轮补） |
| 回灌结果→再学习 | 回灌后**没有自动采 metrics 回流矩阵** | ❌ 断点：`run_exploration_batch` 只返回 ok/status，不接 `record_step`，数据没回流 |
| 探索历史追踪 | 无独立"探索批次"记录 | ❌ 缺 `exploration_history.jsonl`（哪批什么时候探了哪些组合，结果如何） |
| 探索→矩阵联动 | 探索结果不自动写 adaptive matrix | ❌ 缺 `apply_exploration_results`（把回灌数据喂给 `adaptive.run_feedback`） |
| 主动探索 CLI 入口 | `--explore` 只打印建议，不回灌 | ⚠️ 缺 `--explore-run`（打印 + 回灌 + 学习 一次完成） |
| 探索结果 UI 展示 | Web UI 无探索面板 | ❌ 缺 `/explore` 路由 + 前端卡片 |

### 双功能联动的关键断点（最优先补）

```
  学习闭环                    主动探索
  ┌──────────────┐         ┌──────────────────┐
  │ comfyui_     │         │ workflow_explorer│
  │ feedback.py  │──矩阵──▶│ next_exploration │
  └──────┬───────┘         │ _plan            │
         │                 └────────┬─────────┘
         │                          │
         │        【断点①】          │  emit 工作流
         │   探索结果没回流          ▼
         │                  ┌──────────────────┐
         │                  │ emit_comfyui_    │
         │                  │ workflow         │
         │                  └────────┬─────────┘
         │                           │
         │        【断点②】           │  POST /prompt
         │   回灌没采 metrics        ▼
         │                  ┌──────────────────┐
         │                  │ run_exploration_ │
         │                  │ batch            │
         │                  └────────┬─────────┘
         │                           │
         ▼        【断点③】           ▼
  ┌──────────────┐         （没接 record_step）
  │ adaptive.    │◀── 缺 apply_exploration_results
  │ run_feedback │
  └──────────────┘
```

**核心断点**：`run_exploration_batch` → `record_step` → `run_feedback` 链路未打通。
这是"主动探索产生真数据 → 矩阵持续校准"的最后一公里。

## 二、使用人入口规划

### 入口全景（四层）

```
┌─────────────────────────────────────────────────────────────────────┐
│  使用人入口（按角色/场景分层）                                        │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  ① 普通创作者（Web UI）         ② 开发者 / 工程师（CLI）             │
│     browser → /?lang=zh|en        python -m picwf.pipeline_cli     │
│     粘贴剧本+选档位→一键出片      --tier --style --explore          │
│     零命令，填表即出片          全参数可控，可脚本化                 │
│                                                                      │
│  ③ 引擎运营 / 矩阵维护         ④ 数据回流 / 学习闭环（自动）       │
│     /explore 面板（待建）          pipeline_cli --auto-repair       │
│     看探索批次 + 手动触发        跑完自动触发 learn_from_           │
│     下一批探索                   comfyui_runs                       │
│     看矩阵校准前后对比          无需手动操作                        │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 各入口具体布置

#### ① Web UI（普通创作者）
```
GET /?lang=zh    → 中文界面（默认，白皇受众）
GET /?lang=en    → 英文界面

路由规划：
  /              一键出片主面板（已有，i18n 完成）
  /explore       探索面板（待建）
                 - 显示当前 adaptive matrix 前后对比
                 - 显示未验证组合 Top N
                 - 按钮：[触发下一批探索]
                 - 结果：探索批次 + 学习报告摘要
  /history       学习历史（待建）
                 - 按日期展示 record_step 历史行
                 - 趋势图：OOM 率 / 显存峰值 / 耗时
                 - 矩阵校准前后 diff

i18n 现状：
  ✅ 品牌 / 标题 / 卡片 / 按钮 / 错误提示 / 环节名
  ✅ 20 画风 / 10 剧种 / 3 档位 全部中英对照
  ⚠️ /explore 和 /history 路由尚未创建
```

#### ② CLI（开发者）
```
# 出片（日常）
python -m picwf.pipeline_cli \
  --script 剧本.md --tier T1 --style S1_anime_jp \
  --scenario dark_thriller --ep 10 \
  --workdir ./_out

# 出片 + 自动探索建议（跑完附"下一批该试什么"）
python -m picwf.pipeline_cli \
  ... --explore

# 主动探索 + 回灌 + 学习（待建）
python -m picwf.pipeline_cli \
  ... --explore-run --local-models-dir D:\ComfyUI\...\checkpoints
#  会：emit 工作流 → POST ComfyUI → 采 metrics → 回流矩阵 → 打印学习摘要

# 独立学习回流（不出片，只采数据）
python -m picwf.pipeline_cli \
  --learn-only --workdir ./_out
#  会：扫 workdir 历史 → run_feedback → 更新 matrix.adaptive.yaml

# 独立探索（不出片，只看"该试什么"）
python -m picwf.pipeline_cli \
  --explore-plan-only --workdir ./_out
```

#### ③ 引擎运营 / 矩阵维护
```
# 查看当前矩阵状态
cat engine/config/matrix.adaptive.yaml

# 查看探索历史
cat <workdir>/exploration_history.jsonl   （待建）

# 查看学习报告
cat <workdir>/matrix.adaptive.yaml         # 每次 run_feedback 后更新
```

#### ④ 自动数据回流
```
pipeline_cli 主流程
  ↓ auto_repair=True（默认）
  comfyui_feedback.learn_from_comfyui_runs
    → record_metrics.record_step（每次 ComfyUI 实跑）
    → adaptive.run_feedback
    → matrix.adaptive.yaml（矩阵被校准）
  ↓ 下一轮 generate_workflow
  拿到更准的 fallback_chain 优先级
```

### 入口优先级（建议实施顺序）

| 优先级 | 任务 | 价值 | 预估工作量 |
|--------|------|------|-----------|
| P0 | 打通"探索回灌→学习"断点（apply_exploration_results） | 双功能真正联动 | 中 |
| P0 | CLI 加 `--explore-run`（出片 + 探索 + 回灌一次完成） | 创作者无感，跑完自动学 | 小 |
| P1 | 探索历史追踪（exploration_history.jsonl） | 可追溯、可对比 | 小 |
| P1 | Web UI `/explore` 面板 | 运营可视化 | 中 |
| P2 | Web UI `/history` 学习趋势页 | 学习效果可见 | 中 |
| P2 | CLI `--learn-only` | 独立采数据 | 小 |
| P3 | 增量学习（TTL/衰减） | 大规模历史性能 | 中 |
